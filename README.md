## 1. 项目解决的问题与主要功能

### 1.1 项目解决什么问题

DATY RF PRO 用于集中监测无线话筒接收机、查看现场频谱资料、规划工作频率并控制具备相应能力的通道。它把设备和通道状态、扫描数据、固定占用、锁定频率及互调校核放在同一套 Windows 原生界面中，减少逐台查看设备和手工整理频率时的遗漏。

母平台内置 DATYaudio 接入；舒尔设备通过随包提供、需要手动导入的品牌插件接入。跨品牌规划统一计算频率约束，实际监测与控制仍取决于已安装插件、接收机型号、固件和真实能力。

### 1.2 主要功能

| 功能入口 | 当前已实现的功能 | 使用条件或限制 |
| --- | --- | --- |
| 设备概览 / 通道总览 | 查看接收机与话筒在线状态、频率、RF/AF、电池及实时告警 | 以接收机实际提供的字段为准；未知或过期值不补成正常值 |
| 频谱扫描 | 显示设备离散频点；导入 CSV、TXT、`.datyscan` 和受支持的 WWB `.sdb3`；设置峰值与排除阈值；导出 DATY 扫描文件或 CSV | WWB 文件解析需要舒尔插件；扫描曲线仅在当前会话保留，需要留存时手动导出 |
| 接收机在线扫描 | 开始、停止及查询受支持接收机的真实扫描，保留缺失位置和实际结束状态 | 当前限定 ULXD4 / L51，632.125–695.875 MHz、25 kHz 步长；需要已安装舒尔插件和已确认的机身频段；已验证实机仍有一个未解码短尾位置，结果标记为数据不完整 |
| 频率规划 | 联合在线设备实频、扫描峰、固定占用、排除区、锁频和设备 Profile，选择五类互调规则生成分配表与备用频率；导出 CSV / HTML 报告 | 仅监测通道保留原频；数学结果不代表现场所有占用已知，也不代表已下发 |
| 设备管理与控制 | 查看设备与通道、编辑通道资料；对具备能力的在线通道调频、静音和取消静音；核对执行结果 | DATY 使用真实 ACK，舒尔使用独立回读；具体控制以目标通道能力为准 |
| 数据管理 / 系统设置 | 查询已保存的设备及配置资料、导出记录 JSON；保存规划、频谱及显示规则；导入和开发者导出品牌插件 | 业务设置由本项目后台 SQLite 保存，成功状态以真实回执为准；云端插件服务尚未开放 |

### 1.3 项目组成

- C# / WPF 原生界面与可执行程序。
- Python 后台、SQLite 数据存储、MQTT/TLS 通信、设备协议与自动恢复逻辑。
- 前后台共用的频率计算源码与测试。原生界面通过 Jint 使用共享 JavaScript 计算引擎；界面本身由 WPF 实现。
- 独立 Git 仓库、锁定版本的构建工具、运行库、离线依赖及舒尔完整插件包。

这是独立开发环境。首次启动生成新证书、新身份、空配对和空业务数据库，并写入必要的默认设置。运行后的数据由本项目自行保存。

## 2. 系统要求与安装方法

### 2.1 系统要求

- Windows 10 22H2 或 Windows 11，x64。
- 至少预留 6 GB 磁盘空间；后续数据、构建缓存和多次导出会继续占用空间。
- 使用较短的本地路径，例如 `D:\DATY RF PRO`。中文和空格路径已验证；过深目录可能触发 Windows 路径长度限制。
- 保留整个文件夹和隐藏的 `.git`。只复制 EXE 或执行 Git clone，不能带齐被 Git 忽略的工具和离线资源。

项目自带命令行构建工具，不要求另装 Visual Studio、全局 .NET、Python、Node 或 Git；代码编辑器可自行选择。Windows、系统组件与本机安全策略由目标电脑提供。当前 EXE 未签名，不会自动修改 Windows 安全设置。

### 2.2 安装方法

本项目以完整绿色包交付，没有独立安装向导。

1. 获取本项目导出的完整跨电脑开发包 ZIP，或复制已有的完整项目文件夹。生成交付包的方法见第 10 节；仓库源码本身不包含所有被 Git 忽略的工具和运行资源。
2. 将整个包解压到可写的本地目录，例如 `D:\DATY RF PRO`，保留原目录结构。不要直接从压缩包中运行 EXE。
3. 确认根目录有 `DATY RF PRO.exe`，并保留 `native/publish`、`native/assets/plugin-bundles`、`app/tools`、`tools`、`config` 等随包目录。缺少资源时应补齐完整包，不能只复制主程序。
4. 双击根目录 `DATY RF PRO.exe`，等待后台就绪并打开界面。首次运行会初始化本机身份、证书、数据库结构和默认设置。
5. 需要舒尔设备时，再按第 3 节导入本地舒尔完整插件包；首次启动不会自动安装外部品牌插件。

完整交付包首次使用无需编译或联网下载依赖。只有 Git 源码的副本，应先补齐第 5 节列出的锁定工具、离线依赖及插件资源，再运行 `构建原生版.cmd`，不能把 Git clone 视为完整安装。

## 3. 使用方法与日常入口

### 3.1 日常入口

把完整文件夹解压或复制到目标电脑可写的本地目录，双击根目录 **DATY RF PRO.exe** 即可打开，后台自动就绪后进入原生界面。首次运行无需安装、构建或先运行测试。程序不依赖 Codex、SystemAPI、全局 Python 或全局 .NET。

原来的 **启动DATY RF PRO.vbs** 继续可用，使用同一套项目内环境与启停逻辑。根目录 EXE 使用随包携带的原生运行库，不要求 Windows Script Host / VBScript。需要继续开发时，再运行 **检查开发环境.cmd** 和 **运行测试.cmd** 检查完整性并离线编译测试。

| 当前入口 | 用途 |
| --- | --- |
| `DATY RF PRO.exe` | 推荐日常入口；打开前后台，关闭最后一个窗口时正常停止后台 |
| `启动DATY RF PRO.vbs` | 启动后台和原生程序；关闭最后一个窗口时自动正常停止后台 |
| `构建原生版.cmd` | 修改源码后离线构建并发布原生 EXE |
| `运行测试.cmd` | 编译并运行原生核心与契约检查 |
| `检查开发环境.cmd` | 核对交付时的源码和离线依赖摘要 |
| `打开Git.cmd` | 用项目自带 Git 打开当前仓库 |
| `导出跨电脑开发包.cmd` | 生成含完整源码、Git、工具、依赖和当前 EXE 的干净 ZIP |

当前原生程序：`native/publish/r19-native-0.4.61-dev1/DATY.RF.Native.exe`。根目录 `DATY RF PRO.exe` 通过相对路径加载同一发布目录；不重复携带第二套运行库。两个 EXE 与 VBS 都必须留在完整项目中，不能单独复制。根目录入口由 `native/tools/Daty.PortableHost` 自有构建源码及随包 SDK 生成，发布时自动更新。

**关闭最后一个独立项目原生窗口，会自动正常停止该项目后台。** 启动器持续跟踪窗口进程，窗口确认未保存设置后退出；后台随后完成关闭与数据库释放，界面不等待停服而卡住。多个窗口共用后台时，最后一个窗口退出才停服。直接打开当前独立版 EXE 也经过同一启动器。只停止本项目、本次启动身份匹配的后台，不强杀进程、不停止其他目录的服务器或舒尔 SystemAPI。

正常停服结果写入 `runtime/desktop-lifecycle.json`；超时/失败保留日志并提示，不能把窗口消失当作后台已经退出。需要移动或压缩整个运行目录时，等待后台停止。开发维护确需单独停服时，在项目根目录运行 `app/tools/python/python.exe -X utf8 -B scripts/project-local.py stop`。

同一目录仍打开旧版原生窗口时，启动器继续等待旧窗口退出，再关闭所属后台；不会因新版窗口先关闭而遗留后台。

批处理仅保留上表中的五个开发入口：Git、构建、测试、环境检查和跨电脑打包。重复启动、状态查看、独立停服及旧舒尔修复/诊断批处理已移除；项目自带工具内部所需的批处理保留。日常只打开原生软件，`scripts` 内的专项运维脚本不作为日常入口。

软件采用统一入口、统一生命周期：WPF 界面、后台和数据库同属本项目，内部保留独立进程与本机加密通信。打开窗口先确认后台可读写；最后一个窗口正常或异常退出后请求后台完成正常关闭。启动未就绪时清理本次启动的后台；启动器意外退出时，由后台检查本项目剩余窗口并自行正常收尾。所有停止请求绑定实际进程和启动身份，并与新启动互斥；保留其他窗口、其他目录和替代后台，不用强杀代替数据库正常落盘。

### 3.2 推荐使用流程

1. **启动软件**：双击根目录 `DATY RF PRO.exe`，等待读取就绪。没有已接入设备时显示 0 台属于正常情况。
2. **接入设备**：让电脑与接收机网络可互通。DATYaudio 使用项目实际配对配置；舒尔在“系统设置 → 品牌插件管理 → 导入插件”选择 `native/assets/plugin-bundles` 中由 `native/assets/plugin-bundles.json` 登记的当前完整 ZIP，校验后确认“安装并启用”。收到安装回执后，插件在后台自动发现设备。
3. **检查实时状态**：在“设备概览”“通道总览”及“设备管理”核对机型、在线状态、通道和实频。查看 RF/AF、电池及告警时，区分接收机在线、话筒在线和遥测未知状态。
4. **准备扫描资料**：在“频谱扫描 → 导入扫描”选择有效扫描文件；多记录 WWB 文件通过导入按钮旁的选择框切换。也可对受支持且频段已确认的 ULXD4 / L51 点击“开始扫描”，扫描期间可“停止扫描”。调整“扫描峰值阈值”“排除阈值”后检查保存状态；用“导出文件”留存当前记录。
5. **生成规划方案**：进入“频率规划”，在“基本设置”选择或输入范围和互调兼容级别，在“规划约束”设置锁频、排除区及固定占用，需要时配置 Profile 和安全参数。点击“一键全局规划”，检查摘要、实际计算范围、分配表及“详情 / 限制”。
6. **导出或下发**：点击“导出方案”保存 CSV，或“导出报告”保存 HTML。需要实际调频时，点击单通道“下发”或“全部下发”，审查预检及确认清单，等待真实 ACK / 回读。计算或导出方案不会自动调频；接收机调频确认也不代表话筒已同步。
7. **结束使用**：关闭最后一个窗口后等待所属后台正常退出，再移动或打包项目目录。扫描记录仅在当前会话保留；已确认保存的设置与插件安装状态保存在本机数据库中。

### 3.3 输入输出示例

以下数值用于演示文件格式和规则，不是现场测量或实机验收数据。

#### 示例 A：导入扫描 CSV，再导出有效点

将以下内容以 UTF-8 保存为 `example.csv`，通过“频谱扫描 → 导入扫描”打开。表头明确频率单位为 MHz、电平单位为 dBm；TXT 也按扫描表格内容解析，不是任意文字文件。

```csv
frequency_mhz,level_dbm
640.050,-92
640.000,-95
640.025,-45
640.025,-70
```

程序按频率排序，同频重复记录取较高电平，因此得到 **3 个有效频点、1 条重复记录**。点击“导出文件”并选择 CSV，输出为：

```csv
frequency_mhz,level_dbm
640.000,-95
640.025,-45
640.050,-92
```

当扫描峰值阈值为 −60 dBm 时，该示例提取的谱峰为 **640.025 MHz / −45 dBm**。软件内部按整数 kHz 计算，对应频率为 `640025`。缺少单位、空电平或无效数值会使该 CSV 导入失败，不会静默补成 0。

如需保留扫描网格、缺失位置及来源/状态信息，使用默认 `.datyscan` 格式；CSV 只输出有效点，不能完整保留这些信息。

#### 示例 B：规划约束与实际计算范围

在“频率规划 → 规划约束”中，“排除区（MHz）”每行填写起点、终点和可选原因，例如：

```text
650.000-651.000 示例禁用区
```

“固定占用（MHz/kHz）”每行依次填写频率 MHz、保护距离 kHz 和可选原因，例如：

```text
660.000,100,示例固定载波
```

这两行分别表示排除含两端的 650–651 MHz，以及保护 660 MHz 固定占用并让其参与已选互调规则。若用户输入范围为 **640–690 MHz**，当前在线设备实频包含 **632.700 MHz**，当前扫描提取的谱峰为 **632.450 / 633.790 / 673.790 MHz**，则结果摘要中的实际计算范围为 **632.450–690.000 MHz**；数据库仍保留用户输入的 640–690 MHz。

具体分配频率取决于当时的设备能力、Profile、栅格和全部约束，不能从这几行输入预先承诺成功方案。规划 CSV 的实际表头为：

```csv
品牌,设备ID,频率MHz,Profile,可部署
```

每条分配记录包含对应品牌、设备 ID、MHz 频率、Profile ID 及 `true` / `false` 可部署标记；文件只是规划结果，是否已执行需查看下发回执。

#### 示例 C：后台未运行时查询状态

在项目根目录的 PowerShell 中执行：

```powershell
& .\app\tools\python\python.exe -X utf8 -B .\scripts\project-local.py status
```

没有本项目后台运行时，输出：

```json
{"state": "not-running"}
```

后台运行时输出当前实例的实际状态字段。`status` 不启动后台；日常启动仍使用根目录 EXE。

## 6. 配置、数据库与身份

系统设置、规划基本设置/约束及通道显示规则，以后台 SQLite 为权威来源，按类别真实提交。JS、localStorage 或本机 JSON 不保存另一份业务配置权威副本。只有收到真实事务回执，界面才能显示已保存。

| 文件 / 目录 | 用途 |
| --- | --- |
| `config/project-development.json` | 非秘密开发入口、端口及当前原生发布目录 |
| `config/project-instance.local.json` | 本机实例归属、epoch 与 CA 指纹 |
| `config/runtime-config.json` | 启动器生成的后台路径和连接引导 |
| `config/native.local.json` | 原生客户端连接引导 |
| `data/db/daty-rf.sqlite3` | 业务数据库，首次生成包含必需的结构和默认值 |
| `data/security` | 本项目证书、私钥和配对材料 |
| `data/plugins` | 插件安装登记与已安装内容 |

一体版内部使用 `127.0.0.1:18080` / `127.0.0.1:18083` 在本机进程之间通信，不需要用户另开或另配服务器。界面固定连接当前项目后台，侧栏不再提供切换外部服务器的入口，保存连接设置也会校验此绑定。侧栏“局域网”通过内置后台的 `network.status` 获取真实网卡地址，每 30 秒刷新；不把回环地址、客户端网卡或接收机 IP 当作服务器局域网地址。读取失败或断线时清除旧地址；悬停只显示本机网卡及同启同停说明，隐藏内部连接地址。正常启动、自动更新和恢复成功不弹内部连接通知；接收机在线数量的悬停信息独立显示运行状态并使用深色提示。保存及设备操作通知不会被后台刷新覆盖，读取异常仍明确显示并可查看原因，恢复后仅清除对应异常提示。把软件用于局域网接收机管理，需要另外核对监听地址、TLS、配对和插件配置；不能据此把本机开发包称为已验收的现场部署。

同一电脑、同一 Windows 用户移动目录时保持原开发身份，并更新实际路径。复制到不同电脑或不同用户时，使用新的 `.local-instances/<本机摘要>/` 保存身份和数据；其中 `config`、`data`、`runtime` 的含义与上表相同。原电脑私钥不会被新实例读取或覆盖。身份记录损坏或初始化不完整时拒绝直接覆盖，应先排查日志。

清库、历史删除、配对重置和恢复必须有明确范围，不能作为启动失败的默认修复办法。备份数据库应使用一致性方法；不要把正在写入的 SQLite 文件简单复制后称为有效备份。

调整 `config/project-development.json` 中的开发端口前，应先正常停止本项目后台。下次启动会同步原生连接引导，保留刷新周期、数据库和证书身份；运行中发现端口改动会拒绝改写启动配置，原后台仍可正常停止。

首次读取系统设置、规划配置或 Profile 若暂时失败，实时连接恢复后会自动补读。补读保留尚未确认的编辑，不覆盖其他窗口已提交的初始化值，也不重放设备指令。

## 7. 母平台与品牌插件

- DATYaudio 为母平台内置品牌。其他品牌必须在“系统设置 → 品牌插件管理”导入，并由后台确认安装/激活成功后开放发现、监测和控制。
- 附带舒尔 ZIP 只是完整离线资源，文件存在不等于插件已安装。首次独立环境没有已安装的外部品牌，因此首次打开可能显示 0 台；导入后插件自动发现设备，已安装状态随本机数据库保留，再次打开无需重新导入。客户端连接 127.0.0.1 不阻止插件主动发现局域网舒尔接收机。新环境也不继承原服务器的 DATY 配对。
- 插件管理按已安装插件显示；设备和协议状态按实际在线状态显示。两种规则分别判断。
- 舒尔插件直接通过 SCP 自动发现、读取、重连和下发；不要求安装、登录或修复 SystemAPI。完整包只携带 DATY 插件源码、清单与摘要，不再夹带官方安装器；导入按包内结构识别，兼容已审核的旧完整包，但不会启动其中的官方安装器。已安装插件在本项目下次正常启动前自动升级到当前配套版本，未安装或已移除的品牌不会自动安装。
- 开发排查舒尔接入时，可在问题电脑保持 DATY 窗口打开，从项目根目录运行 `app/tools/python/python.exe -X utf8 -B scripts/project-diagnose.py --target 接收机IP`。报告生成在项目根目录，检查目标 TCP/SCP GET、当前后台插件及自动发现状态、以及当前监测健康状态。显式加 `--reference-systemapi` 才做官方参考比较，结果不作为接收机上线条件。常规上线不需要此工具。只读取状态，不调频、不静音、不全网扫描、不更改数据库；报告不含认证密钥、证书内容或业务设置。
- 旧固件不回复 MODEL 时，依据实时 SCP 机身和通道字段组合选择兼容协议，标记为兼容识别，不伪称接收机上报了型号。下发自动核对当前目标/通道、数值和独立回读。已知硬件频段仍限制越界；直接接入的旧 ULXD 不报告频段时，允许在平台命令范围 400–900 MHz、25 kHz 步进内发起调频，由接收机执行能力与回读判定结果。这是命令范围，不能作为硬件频段或可用频谱承诺；接收机未接受时不会显示成功。完整 RF 扫描使用下文的独立插件会话和已验证机身频段。
- 保持现有开发者导出流程及服务端插件状态确认；导出后移除插件涉及停止该插件管理，不能只改变前端显示。

导入时，文件读取、ZIP 校验和操作意图落盘在后台执行；舒尔完整包只做一轮必要预检。收到匹配的真实安装回执后立即更新插件卡片，接收机发现另在后台进行，不用发现完成作为安装完成的条件。安装回执未知时只查询原操作，不重复提交安装。开发诊断可捕获 `PLUGIN_IMPORT` Trace，区分本地校验、服务预检、意图落盘及回执耗时；这些时间不代表全部现场网卡发现时间。

### SystemAPI 学习与自有实现

SystemAPI 用于研究接口设计，再以 DATY 自有源码整合进频率规划软件。根据官方公开接口及可观察行为独立实现；DATY 母平台直连 DATY 产品，其他品牌继续通过可完整导出的源码插件接入。

参考 [Shure SystemAPI 官方介绍](https://www.shure.com/en-US/products/software/systemapi) 与本机公开 API 文档。此次已读取接口中的设备/通道能力、设备订阅和发现地址管理结构；不把官方能力声明当作 DATY 已实现或实机已验证的能力。

| 学习方向 | DATY 自有实现与约束 |
| --- | --- |
| 统一设备与通道模型、能力发现 | 母平台统一快照，插件解析实际型号、通道与字段；按实际协议能力开放控制 |
| 实时订阅与恢复 | 接收机独立 SCP 监测会话，通过现有 MQTT 数据流更新原生界面；字段时间、过期与断流分别处理 |
| 自身健康可观测 | 插件返回 `health`：有效接收机、监测会话、过期/恢复状态和最近错误；关闭及断线不保留虚假在线计数 |
| 控制结果可核对 | 复用 DATY 持久命令事务、在途保护与独立实际回读；收到或发出请求不等于执行成功 |
| 轻量独立部署 | 当前插件完整包 `runtimes=[]`，导入、运行、导出与跨电脑交付不要求官方服务或认证材料 |

`shure_systemapi.py` 和旧官方维护工具仅为明确调用的参考/历史绑定兼容源码，不是当前直接接入前提；保留历史机身标识，避免既有频段资料和回执失配。常规诊断不导入或请求官方接口。以后新增功能先落到自有源码、真实数据库和隔离测试；未验证机型/频段的完整 RF 扫描、固件升级等能力不因参考软件存在就宣称已具备。当前 ULXD4 / L51 直接扫描的已实现范围与数据完整性限制见第 8 节。

### 频率规划与品牌下发

“兼容级别”使用五个独立复选项：**2T30、2T50、2T70、2T90、3T30**。对应源码规则 ID `2T3O/2T5O/2T7O/2T9O/3T3O`（O 为 order）。两源公式依次为 `2f₁−f₂`、`3f₁−2f₂`、`4f₁−3f₂`、`5f₁−4f₂` 及交换两源的对称式；三源为 `f₁+f₂−f₃` 的三种组合。只使用整数 kHz，计算频率位置与保护距离，不估算产物功率。术语可参照 [SoundBase 官方说明](https://docs.soundbase.app/guides/zones/editing-zone-settings/)，工程实现为本项目独立源码。

勾选项按 `settings/frequency_planning.fields.plannerImdProducts` 即时写入 SQLite；重开恢复原值，未勾选的互调类型不会被后台隐式打开。允许全不选，此时仍校验设备范围、频率栅格、通道间隔、扫描与占用。旧库没有新字段时从原三阶/五阶策略映射，不改写旧修订；原 Profile 间隔参数保留，品牌保护间隔可在详情查看，不把旧三档名称冒充新的互调算法。

一键全局规划联合使用当前在线设备实频、手填固定占用、人工锁频、排除区及当前会话的真实扫描。所有达到峰值阈值的实测谱峰参与所选互调规则，保留原始频率精度；同频条目合并。计算范围自动取用户输入边界与设备实频、锁频、固定占用、扫描峰的最小至最大值，不用噪底全图边界扩展。例如输入 640–690 MHz，设备 632.700 MHz、扫描峰 632.450 / 633.790 / 673.790 MHz 时，实际范围为 632.450–690 MHz。摘要显示实际范围，详情列出参与谱峰；数据库保留用户原始范围设置。扩大范围不移动规划栅格原点，不突破接收机真实硬件频段和步进；规划、备用、手动频率校核及下发预检采用相同规则。当前实频对其他通道继续保留占用，自身保留原频不重复算源；同一占用的重复条目合并并保留较严格保护。固定占用同时作为互调来源及被保护频点。仅监测或当前没有已验证调频能力的在线设备作为背景占用，不被移频，也不进入下发清单；范围外背景仍参与相关互调校验。扫描峰只表示实测频点，不推定已识别发射机；没有扫描或覆盖不足，不能宣称已获知现场所有占用。

规划与下发分开：计算产生可审查的频率表；点击“全部下发”先预演整个 GROUP/CH 顺序，再显示确认清单。每条指令发送前仍复核当前身份、通道、品牌、频段、调谐栅格及与尚未移频设备的冲突。DATY 使用原生 MQTT 执行 ACK，已安装的舒尔插件使用 SCP 下发和独立回读；其他品牌按实际已安装且实现的插件能力接入，不把未知协议当作可控制。确认接收机调频不等于话筒已同步，本轮原频占用不会因此自动释放。失败或结果未知即停止后续，不自动重发。

定向验证还包括 `scan-peak-coordination.test.cjs` 与原生 `PlanningScanSourceCases`：四个实测频率全参与 3T30、自动范围并集、离栅格峰、扫描缺口及手动/下发一致性；所有测试使用隔离夹具，不调谐现场设备。定向验证包括 `app/server/tests/imd-products.test.cjs` 的五类独立算术/组合与占用保护，`test_planning_settings_mqtt.py` 的真实 SQLite/MQTT/TLS 保存恢复，原生 `MonitoringPlanningCases` 的背景与整批预演，及 `PlanningFixture` 的真实复选控件跨进程保存。证据保存在 `verification/planning-imd-*`；本次开发验收不向现场接收机调频。

### ULXD4 扫描文件与直接扫描

频谱设备频点沿用数据库的话筒接收状态：离线或测量未知时保留实际频率，在图底部显示灰色状态标记，不绘制绿色 RF 柱，也不把底部位置伪称为 −110 dBm 实测值；恢复有效新鲜接收后才按实际 RF 绘制。ULXD 的新鲜天线 XX 即使同时报告变化的底噪，也不表示话筒上线；规则尚未读到或遥测过期时不沿用旧绿条。原始 RF 报文与真实扫描曲线保持原值。

频谱扫描已取消仿真曲线、噪底、互调仿真区域及对应计算，不再从接收机 RF 单点生成连续曲线。保留真实接收机离散频点与导入文件曲线；底部原工具/状态行保持移除。导入多记录 WWB 文件时，记录选择位于上方导入按钮旁。

频谱 Y 轴固定为 −20 至 −110 dBm，每 10 dBm 标注主刻度、每 5 dB 为暗色细格；频率网格按当前范围对齐 1/2/5 系列主刻度及五等分细格。绘图区采用黑底，主格与细格明暗区分。超出纵轴的曲线仅裁剪显示，原始扫描值及规划数据不变。

图表上方提供两项数值设置：橙色“扫描峰值阈值”首次为 −60 dBm，红色“排除阈值”首次为 −85 dBm，范围 −140～0 dBm。有效输入或上下微调立即按 `settings/spectrum_scan` 类目提交 SQLite；重开及跨窗口读取已有值，不重复初始化。读取前禁用编辑、不画默认阈值；保存失败显示未保存，未知回执先核对，不能据界面变化当作数据库已保存。

峰值阈值提取真实扫描中连续超阈区的最高采样点，作为固定占用参与已选互调规则计算；同高平台取实际中间点，不推定发射机身份。排除阈值作用于有扫描数据的频率规划，最终与设备 Profile、规划安全参数取更严格值。红色底部标记只表示实测超阈采样段，不代表完整硬件保护带。缺失点和过大采样间隙不连接、不填噪底；阈值参考线及悬停说明与扫描来源独立。

上方工具栏统一 30 像素高度、边框、字体和间距，窄窗口自动换行。“开始扫描”在扫描期间变为“停止扫描”；导入、清除和记录切换等待本次扫描结束。详情放在悬停说明中。

“导出文件”默认生成 `.datyscan`，保留当前记录的实测值、网格、缺失位置、来源及扫描状态，可重新导入；也可导出只包含有效实测点的 CSV。导出正在扫描或不完整记录时保留原状态，不补造采样值。

在“频谱扫描”点击“导入扫描”，选择 `.sdb3`、`.datyscan`、CSV 或 TXT。WWB 文件由已安装的舒尔插件解析；安装过的插件在下次启动时升级，未安装舒尔插件的独立环境仍须先导入插件。当前支持已验证的 WWB7 / ULXD4 单曲线双记录 SDB3 格式，最大 128 KiB；其他格式明确报不支持，不猜测解码。

导入后可选择文件记录，悬停查看“WWB 文件”、记录及原始采样值。保留原始频率、电平及缺失位置；缺失处断线，不填补成噪声底。规划只使用有效测量，并按文件网格限制未知间隙。文件与记录仅用于当前会话，不保存扫描历史；校验失败、取消或断线不会替换已导入的曲线。文件不含可核实的接收机 IP/MAC，不自动绑定在线机身，也不把文件校验通过解释为硬件扫描完成。

ULX-D 的完整在线扫描在 WWB 中受官方支持。2026-10-07 已取得本机 ULXD4 的完整自然扫描、取消及重扫记录：完整扫描 150 个标准数据块、2550 个有效点，与对应 WWB 原文件逐点一致；取消记录为 323 点，之后重新扫描的 2550 点也全部一致。用户命名的 `4.sdb3` 对应取消那次，完整重扫数据保存在 WWB 自动文件及本次验证目录中，不能仅凭文件名判断是否完成。

已加入两项纯离线源码基础：`app/server/shure_scan_endpoint.py` 从实际 SLP 公告解析动态 SDT 端点候选；`app/server/shure_scan_wire.py` 有限额地解码 ACN/SDT/DMP，并按显式网格、独立会话装配扫描点。缺点保持空，未知短尾报文保留原始数据，重复幂等、冲突原子拒绝；不固定本次 IP、UDP 端口或 WWB 身份。候选发现不代表已连接，网格覆盖完整不代表设备报告完成。这些基础模块来自 Git `45e83ea`，现由舒尔插件内的自有 UDP/SDT 客户端调用。新客户端生成自己的 CID、端口和会话序号，经动态端点发现、双向连接和状态确认后才接受扫描；不依赖 SystemAPI。扫描前由自有 `shure_scan_session.py` 完成本次连接的会话协商：读取当前参数、生成新公值、回读会话确认，再设置扫描参数；不沿用 WWB 历史会话值、不修改接收机 PIN 或访问控制。

实测取消与自然结束都会出现相似的结束状态，正常结束后也有客户端清理指令，不能单凭其中一条判成功或取消。自然扫描的进度 100、点数据及结束顺序已观察到，短尾语义及现场异常断线/连接恢复仍须继续验证。TCP 2202 的当前通道 SAMPLE 不能替代全频段扫描。2026-10-07 重查本机 SystemAPI：REST 没有扫描接口，内部 GraphQL 确有 RF 扫描，但当前旧固件被官方判定不支持。对照原生流程与 WWB 报文，直接客户端补齐了会话协商，以及此前遗漏的扫描资源申请：读取 RF_SCAN:SCAN_ID 取得本次资源后，才能用该标识开始；取消和结束也只释放本次资源，不能硬编码 0。协商失败、超时、收到忙碌状态或提前取消时，不发送开始扫描；收到传输 ACK 不当作设备执行。开始后 10 秒未取得设备确认会明确报错，不自动重发。证据见 `verification/systemapi-scan-readonly-20261007/report.md` 和 `verification/systemapi-keyexchange/independent-protocol-facts.md`。

2026-10-07 修复后已通过一台 ULXD4 / L51（固件 2.3.34.0）实际自然扫描：独立申请扫描编号、设备确认开始、收到 2550 个有效点、设备自然结束、释放本次资源并完成真实数据库回执。独立录包与返回数据逐点一致。695.875 MHz 的短尾位置仍未解码，保留 1 个空值，结果明确标记为数据不完整，不伪称全网格完成。实机证据见 `verification/scan-session-acceptance-20261007-144735/acceptance-audit.md`。

当前直接扫描限定于已有证据支持的 ULXD4 / L51 网格 632.125–695.875 MHz、步长 25 kHz。设备报告的 L51 身份，或数据库 `settings/shure_scan_profiles` 中按 MAC 和机型绑定的已确认机身标签，决定可用性；不按当前调谐频率猜频段，不固定 IP。当前已验证编号 0 的点数据；若接收机分配其他编号，只归还本次资源并说明暂不支持，不抢占其他客户端的扫描。旧固件对扫描配置 GET 返回不支持时保留真实空值，明确使用已确认机身资料。

新环境不携带旧机器的机身绑定。旧 ULXD4 在线但不报告频段时，点击“开始扫描”可进入“扫描频段”，按实际机身标签确认 L51 后保存。该资料按当前接收机 MAC 写入数据库并读回核对，刷新扫描能力，无须重新导入插件或重启；保存不会自行开始扫描。报告其他频段的机身不能用 L51 标签记录覆盖，未知机型、缺少机身 MAC 或已离线时不能据 IP 猜测绑定。

开始请求先保存操作回执；收到请求、传输 ACK、设备结束、采样覆盖完整分别处理。只有设备结束、全网格有效点、清理完成和最终回执落盘全部满足才显示完整结果；未知短尾仍按缺失位置处理。扫描点仅保留有界会话缓存，数据库只保存机身配置及操作摘要。断线查询原操作，不自动重新扫描；卸载插件、关闭所属窗口或停止后台会清理本次会话。参考：[官方支持表](https://content-files.shure.com/Pubs/WWB/en-US/en-US/supported-features.html)、[官方扫描帮助](https://content-files.shure.com/Pubs/WWB/en-US/en-US/scanning.html)、[WWB 端口说明](https://service.shure.com/articles/en_US/Knowledge/wwb6-ports-and-protocol-information)。

用户确认协助后，可双击 `scripts/采集ULXD4扫描.vbs` 准备实际通信证据。先退出 WWB，输入目标接收机 IP，按工具提示开始采集，再在同一电脑打开 WWB 做一次扫描，等待自然完成并保存 `.sdb3`。双击入口使用独立 IP 层采集，最多 600 秒；只持久化目标 IP 的 IPv4 包，不自行控制接收机，不开启网卡混杂模式，不安装驱动。输出在 `verification` 的独立目录，需要管理员权限。不要求做断网演练。

专项命令为 `app/tools/python/python.exe -X utf8 -B scripts/project-shure-scan-capture.py --target 接收机IP --engine raw-ip --capture --seconds 600`；不加 `--capture` 只打印计划，`--check` 只检查本机准备条件。`--interface 本机IPv4` 可显式选卡，默认根据 Windows 到目标的路由选择。独立接收线程持续写入标准 LINKTYPE_RAW 的 pcapng，达到体积上限即停止并保留较早握手，不循环覆盖。实现依据 [Microsoft SIO_RCVALL 文档](https://learn.microsoft.com/en-us/windows/win32/winsock/sio-rcvall)，使用 `RCVALL_IPLEVEL`。

人工 S/N/C/D/R 标记是观察时间，不能代替设备事件；Q 正常结束采集。隐藏子进程持有真实父进程句柄，窗口退出或到时后关闭所属采集，最终结果另存 `watchdog.json`。IP 层方式关闭自身套接字，不修改全局 PktMon 会话；系统失去响应或进程被强制终止时仍需查看最终回执。保留 pcapng、WWB 原文件和摘要报告供逐点核对，不保存其他 IP 的内容。严格目标 IP 筛选可能漏掉本机多播控制包，文件存在也不能证明捕获完整。此工具是开发辅助，不是日常启动依赖。

保留 `--engine pktmon` 用于其他协议交叉核对；它需要 Windows 自带 PktMon，拒绝覆盖已有会话或过滤器，输出 ETL 与 pcapng。2026-10-07 两次 PktMon 实测均缺失大量扫描包，原 ETL 与转换结果逐帧一致，因此不能再仅凭“系统丢失事件为 0”宣称扫描记录完整。替代 IP 层方式的短时 UDP 连续性检查通过，但本机未收到接收方向 TCP；两种采集的证据范围不同，完整扫描仍须逐点对照 `.sdb3`，完成/取消仍须独立验证。

## 10. 导出与跨电脑继续开发

1. 在当前项目完成修改和必要测试，提交需要交付的源码。
2. 提交后运行 `构建原生版.cmd`，生成当前原生程序、根目录 EXE 和发布摘要，确保程序对应当前 Git 提交。
3. 运行 `导出跨电脑开发包.cmd`。Git 工作区不干净、文件丢失、依赖摘要不符、程序缺少自包含运行库或不是当前提交的发布结果时会拒绝完成。
4. 将 `delivery` 中最新 ZIP 和同名 JSON 回执复制到目标电脑，解压到较短路径。
5. 双击根目录 `DATY RF PRO.exe` 使用；需要开发时按第 3 节检查、测试，在该目录继续开发。

ZIP 包含已提交源码、完整 Git、固定工具/依赖和当前发布 EXE；排除数据库、私钥、配对、已安装插件状态、日志和构建缓存。每次交付带源码、依赖及传输清单和 SHA256 回执。

完整跨电脑开发包用于受信任环境之间迁移，可能包含本地保留的原始 Git 历史，不作为对外公开源码包。上传源码仅推送经核验的 `main`；不要直接公开整个工作目录、历史备份或开发包 ZIP。示例配置使用项目相对路径和文档示例地址；诊断工具的目标地址应显式提供。历史对照测试需要通过各自的环境变量提供基线，不依赖原开发电脑的目录。

`config/portable-release.local.json` 记录发布对应的源码提交，以及根目录入口和自包含程序的逐文件摘要；导出前逐项核验，不允许只更新显示版本而携带旧程序。新电脑会生成自己的身份和空数据库。舒尔完整插件仍在包内，按第 7 节导入后自动发现；不需要另装 SystemAPI。

跨电脑包使用标准 ZIP Deflate 压缩，交付文件必须小于 **1,000,000,000 字节**，超限会保留未完成文件并报错。完整舒尔包只保留在 `native/assets/plugin-bundles` 一处，独立原生版从项目根目录读取并校验，不再复制到每个发布目录。源码、SDK、Git、Python、Node 和离线 NuGet 全部保留；当前交付清单排除 SystemAPI 安装器及旧插件包。这里限制的是压缩包大小；解压及后续编译需要更多空间。

`检查开发环境.cmd` 对照的是交付快照。修改源码后出现摘要不一致是正常提示，不应删除改动或伪造清单；审查并提交后重新导出会生成新的快照。Git 历史用于追溯，不作为当前操作说明。

## 11. 常见问题

| 现象 | 排查方式 |
| --- | --- |
| 首次启动失败 | 查看当前实例 `runtime/project-launch-error.log`、`runtime/launcher.log` 和服务日志；核对完整目录及 Windows 运行限制 |
| 端口已占用 | 确认是否已有本项目后台；不要强制结束其他程序或创建第二个写入实例 |
| 界面显示正在连接 | 核对当前实例 `runtime/runtime-status.json` 的传输就绪和持久化状态；进程存在不等于业务可用 |
| 找不到 SDK / 离线包 | 运行环境检查，核对 `tools`、`app/tools` 和依赖清单；不要临时引用原电脑绝对路径掩盖缺失 |
| 解压或构建提示路径过长 | 把完整项目移到更短路径后重试 |
| 复制后仍有旧数据目录 | 不同电脑的新实例位于 `.local-instances`；需要不携带任何旧状态时使用干净导出包 |
| 舒尔设备未出现 | 先检查插件实际安装/激活状态，再核对接收机网络、机型与插件日志 |

需要从命令行只读查看当前后台状态时，在项目根目录执行：

```powershell
& .\app\tools\python\python.exe -X utf8 -B .\scripts\project-local.py status
```
